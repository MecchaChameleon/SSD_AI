# 제주 유동인구 기반 수요예측 EBM 모델 — 인수인계

## 현황
`jeju_ebm_demand.py`를 실행하면 데이터 수집 → 피처 엔지니어링 → EBM 학습 → 테스트 평가까지 한 번에 완주됩니다.
기존 월 단위 모델과 별도로 `train_daily_flow_ebm.py`를 실행하면 제주데이터허브 최근 3년
일별 표본을 수집하고 가격 서버용 `artifacts/daily_demand_profile.json`을 생성합니다.

```
pip install pandas interpret holidays python-dotenv requests   # Python 3.8 기준
python jeju_ebm_demand.py
```

시각화가 필요하면 `python build_dashboard.py`로 `dashboard_data.json`을 갱신한 뒤 `dashboard_template.html`과 합쳐 `dashboard.html`을 다시 만들면 됩니다. 현재 대시보드: https://claude.ai/code/artifact/a824f782-ef59-45d7-8e44-de59d11dbbf1

## 결과
- **MAE**: 40,877 / **MAPE**: 13.50% / **R²**: 0.9358 (테스트 3개월: 202511~202601)

## 꼭 알아야 할 설계 변경 사항

1. **타깃 grain: 읍면동×일 → 읍면동×월.** 원 설계는 일 단위였으나 실제 확보한 `제주 지역별 방문객.csv`가 `기준연월(YYYYMM)` 단위로만 제공되어 재설계함. 이에 따라 lag/이동평균도 lag1(전월)/lag12(전년동월)/ma3(3개월 이동평균)로 대응.
2. **유동인구 비율은 "그 달 실측값"이 아니라 "달력월 계절 평균".** `제주도방문내국인유동인구추이.csv`에는 읍면동 구분이 없고(전국 집계), 기간도 2025-04에서 끝나 타깃 기간(~2026-01)을 못 채움. 그래서 night/young/female_ratio는 2018~2025 전체 이력을 달력월(1~12)별로 평균 낸 계절 프로파일로 대체 — 모든 읍면동에 동일 적용됨.
3. **ASOS 기상 데이터는 API가 아니라 로컬 CSV.** data.go.kr `AsosDalyInfoService`는 활용신청 승인 후에도 게이트웨이가 계속 `403 Forbidden`을 반환해서, data.kma.go.kr(기상자료개방포털)에서 받은 시간자료(hourly) CSV `OBS_ASOS_TIM_20260714225401.csv`로 대체. 스크립트(`load_weather_monthly()`)가 시간→일→월 집계를 직접 수행. 지점은 제주시=184, 서귀포시=189로 매핑.
4. **입도 관광객 CSV는 재다운로드로 기간을 맞춤.** 처음 받은 파일은 2025-01~2026-01(13개월)뿐이라 lag12(전년동월)를 못 채웠음. 202401~202601 전체로 재다운로드해서 해결.
5. **소상공인 상가정보(#5)는 이번 라운드에서 제외.**
6. **C-ITS 교통 데이터는 애초에 학습에서 제외** (실시간성이라 과거 데이터 구축 불가, 원 설계 방침 그대로).

## 실시간 AI 가격 서버

`app/`은 제주데이터허브 최근 3년 일별 유동인구로 학습한 EBM 수요 프로필에 상품 재고,
판매 경과 시간, 현재 날짜·요일·공휴일·상품 읍면동, 기상청 제주 초단기실황·3시간 예보를
결합해 최소가와 정상가 사이의 추천가를 계산한다. 유동인구 API는 추론 시 호출하지 않으며,
학습 아티팩트가 없을 때만 기존 월별 방문객 프로필을 사용한다. 가격 화면에는 SHAP 대신
정책 중립점 대비 `판매 경과 시간`, `잔여 수량 및 재고 변화량`, `날씨`, `지역 수요`가
추천 가격을 올리거나 내린 원 단위 금액을 직접 계산해 표시한다.
내부 정책 할인 압력 3~65%는 실제 할인 상·하한이 아니라 판매자 가격 범위상의 위치로 사용한다.
압력 3%는 판매자 최대가, 65%는 판매자 최소가에 매핑되어 설정 범위 전체에 도달할 수 있다.

```dotenv
DATA_GO_KR_KEY=공공데이터포털_인증키
JEJU_DATA_HUB_KEY=제주데이터허브_프로젝트키
KAKAO_REST_API_KEY=카카오_REST_API_키
```

```powershell
python train_daily_flow_ebm.py
```

현재 학습 데이터는 2023-06-02~2026-05-31의 51,300행, 1,095개 날짜(3년 날짜 커버리지
100%)이며 읍면동 43개를 포함한다. API의 일일 쿼터와 요청당 100행 제한 때문에 3일 구간별
표본을 수집한 뒤 누락 날짜를 일별 조회로 보충한다.

날씨는 제주 좌표만 기상청 5km 격자로 변환해 조회하고 결과를 10분간 캐시한다. 기상청 장애
시 Open-Meteo로 대체하며, 모든 외부 입력 장애 시에도 기본값과 과거 EBM으로 추천을 계속한다.

```powershell
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 9000
pytest
```

### Render 배포

BE와 무료 실행 시간을 분리하기 위해 AI는 BE와 다른 Hobby 워크스페이스에 배포한다.

1. 이 디렉터리를 별도 GitHub 저장소에 push한다. `.env`는 커밋하지 않는다.
2. Render에서 AI용 Hobby 워크스페이스를 만들고 **New → Blueprint**로 저장소를 연결한다.
3. Blueprint 생성 화면에서 다음 환경변수를 입력한다.
   - `AI_SERVICE_API_KEY`: 충분히 긴 임의 문자열
   - `DATA_GO_KR_KEY`: 공공데이터포털 인증키
   - `KAKAO_REST_API_KEY`: 카카오 REST API 키
4. 배포 후 `https://<AI 서비스 주소>/health`가 `{"status":"ok", ...}`를 반환하는지 확인한다.
5. BE 워크스페이스에 다음 값을 입력하고 BE를 재배포한다.
   - `AI_SERVICE_BASE_URL=https://<AI 서비스 주소>` (끝의 `/` 제외)
   - `AI_SERVICE_API_KEY=<AI에 입력한 것과 같은 값>`

서로 다른 워크스페이스의 서비스는 Render 사설망으로 연결할 수 없으므로 공개 HTTPS 주소를
사용한다. 가격 및 전략 API는 `X-AI-Service-Key` 헤더를 검사하므로
`AI_SERVICE_API_KEY`를 비워둔 채 운영하지 않는다.

백엔드는 로컬 개발 시 기본적으로 `http://localhost:9000`을 호출한다. 로컬 PC를 임시 AI
서버로 사용할 때만 `start_ai_tunnel.cmd`의 Cloudflare Quick Tunnel 방식을 사용한다.

## 다음 작업 (진행 중 중단)

예측 방문객수로 읍면동 단위 **할인율**을 정하는 로직 설계 중이었음. 합의된 방향:
- 기준점: **같은 읍면동의 과거 분포 대비 백분위**로 이번 달 예측치가 저수요/고수요인지 판단 (예: 하위 20%면 저수요 → 큰 할인)
- 적용 단위: **읍면동 단위** (모델의 예측 grain과 동일)
- 아직 구현 전 단계 — 구체적인 백분위→할인율 매핑 함수(예: 몇 단계 구간, 최대/최소 할인율)는 미정.
